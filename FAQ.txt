 Часто задаваемые вопросы по Git

В чем разница между git fetch и git pull?

git fetch загружает новые данные из удаленного репозитория, но не применяет их к вашим локальным файлам. Он только обновляет информацию о том, какие изменения есть на сервере. git pull делает то же самое, но затем автоматически сливает изменения с вашей текущей веткой. git fetch безопаснее, так как вы можете сначала посмотреть, что изменилось, а потом решить, нужно ли это сливать.

Как исправить последний коммит, если забыл добавить файл?

Если вы только что сделали коммит и забыли включить в него какой-то файл, добавьте его, а затем обновите последний коммит. Если нужно также изменить сообщение коммита, это тоже возможно. Важно не использовать эту технику для коммитов, которые уже отправлены в удаленный репозиторий, если с вами работают другие люди.

Что такое staging area и зачем она нужна?

Staging area (область подготовки, индекс) — это промежуточная зона между вашими рабочими файлами и репозиторием. Она позволяет выборочно включать изменения в коммит. Вы можете изменить пять файлов, но закоммитить только три из них.

Как временно переключиться на другую задачу, не теряя текущие изменения?

Используйте git stash — он временно сохраняет ваши незавершенные изменения и возвращает чистый рабочий каталог. После того как вернетесь к своей задаче, примените сохраненные изменения.

Что делать, если случайно удалил коммит?

Не паникуйте! Git сохраняет историю всех действий. Посмотрите историю, найдите хеш нужного коммита и восстановитесь на него. Это работает, если вы еще не запускали сборку мусора.

Как отменить коммит, который уже отправлен на GitHub?

Используйте git revert — он создает новый коммит, который отменяет изменения старого. Это безопасно для командной работы, так как не переписывает историю.

Что такое .gitignore?

.gitignore — это файл со списком файлов и папок, которые Git должен игнорировать. Туда обычно добавляют временные файлы, артефакты сборки, папку с зависимостями и файлы с секретами (например, .env). Важно знать, что добавление файла в .gitignore не влияет на файлы, которые уже отслеживаются Git.

Что делать при конфликте слияния?

Конфликт возникает, когда две ветки изменили одни и те же строки в одном файле. Git помечает конфликтные места в файлах. Вам нужно вручную отредактировать файл, оставив нужные изменения, удалить служебные маркеры, а затем завершить слияние.

Как объединить несколько коммитов в один?

Можно объединить несколько коммитов в один, чтобы сделать историю чище и понятнее. Это особенно полезно перед отправкой pull request.

Как посмотреть историю коммитов в удобном виде?

Стандартный git log показывает много информации. Можно использовать сокращенный вариант для краткого вида, посмотреть граф веток, ограничить количество коммитов или искать по сообщению.
